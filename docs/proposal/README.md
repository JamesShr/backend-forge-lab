# Proposal

Proposal 文件放長期方向與能力模型，不記錄日常實作進度。

## 文件

| 文件 | 說明 |
|---|---|
| `roadmap/levels.md` | L1 到 L4 能力定義 |
| `roadmap/domains.md` | Backend Engineering domains |
| `roadmap/skill-matrix.md` | 各領域建議目標深度與優先級 |
| `roadmap/stages.md` | 建議學習階段 |
| `roadmap/learning-loop.md` | 每個主題的學習循環與紀錄格式 |
| `roadmap/outcome.md` | 最終能力定位 |

## Roadmap 摘要

Backend Forge Lab 的學習計畫不追求一次把所有技術學到最深，而是採取：

```text
L1: 建立概念地圖
L2: 能獨立實作
L3: 能處理 failure / load / reliability 問題
L4: 能做 architecture trade-off 決策
```

Roadmap 定義要學什麼，Backend Forge Lab 負責把適合實作的主題轉換成可執行實驗。

## 排程原則

學習順序採取「先廣度，再深度」：

```text
先讓主要 domain 都有 L1/L2 接觸
        ↓
再挑高價值主題推進 L3
        ↓
最後只針對少數主題整理 L4 trade-off
```

不要把 roadmap 理解成先完成某個 domain 的所有 L3/L4 labs，才開始下一個 domain。
